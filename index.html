Profile

I am an independent researcher working in computer architecture, FPGA design, and hardware generation.

In my third undergraduate year, I studied computer architecture on my own, from online material. I then tried to write an out-of-order superscalar RISC-V CPU without supervision. The work was much harder than I expected, and I did not finish it. That attempt decided the direction of everything I have done since. As a master's student, I first built the tool I had been missing: Kathryn, a framework that hides most of the low-level design work. Chisel was the inspiration. I then used Kathryn to build Kride, an out-of-order RISC-V core that runs programs compiled with the standard GCC toolchain.

At CERN, I studied partial reconfiguration for machine learning on FPGAs. With partial reconfiguration, an FPGA can load new parts of itself while it is running. A small FPGA cannot hold a whole model, but it can still run one, by loading one part of the model at a time. This work became DFX4ML. I also wrote the Vitis Unified backend for hls4ml.

Kathryn: cycle-accurate hardware design framework Chulalongkorn University

A hardware construction DSL in Rust and Python: abstract control flow, decentralized update, and hardware aggregation, with no structural RTL. The legacy C++ version is under review at IEEE TCAD.

github.com/Tanawin1701d/Kathryn · kathryn-tools.org

Under review at IEEE TCAD · paper (PDF)

  • Host-language abstraction: the model is written in C++, so templates, inheritance, and object-oriented reuse describe and parameterize the hardware.
  • Hybrid Design Flow: control flow as blocks; stalls, kills, and back-pressure are handled by the framework.
  • Decentralized update: a resource is updated where the event happens, not at one driver.
  • Hardware Aggregator: many entries managed as one bundle.
  • Result: 67.85%, 63.55%, and 56.67% fewer control, data, and total lines than the RIDECORE Verilog, same cycle behavior.
  • Size: 27,321 lines of C++ across 410 files in the legacy version; 12,709 lines of Rust and 1,308 of Python across 224 files in the current one. Source only, tests excluded, measured with cloc.

Kride: out-of-order superscalar RISC-V core Chulalongkorn University

An out-of-order superscalar RV32I core written in Kathryn, re-implementing the Verilog core RIDECORE, and the case study of the IEEE TCAD submission. It runs programs compiled with the standard GCC toolchain, with a custom linker script and no system calls.

kathryn-tools.org/cppbook/kride · built in the Kathryn repository, src/example/o3

  • Six stages, a two-wide in-order front end, a multi-lane back end, five reservation stations, a reorder buffer, and exact misprediction recovery from five speculative tags.
  • Bit-exact against RIDECORE over ten workloads and 2,231,367 cycles; on a Kria KV260 the board matches simulation cycle for cycle.

Carolyne: ISA-agnostic out-of-order CPU generator

Carolyne separates the ISA from the microarchitecture. Currently in progress.

github.com/Tanawin1701d/Carolyne

Work in progress, currently building

  • The engine is written once, against a fixed µop contract. A new ISA arrives as a Python description package, from which the engine builds its rename tables, decoders, register files, and commit logic.
  • Aim: an out-of-order core for a new ISA without designing a microarchitecture. First target: RV32I and a mini-x86.

DFX4ML: CPU-free partial reconfiguration for ML inference CERN

A small FPGA cannot hold a large model, so DFX4ML reloads parts of itself while it is running.

github.com/Tanawin1701d/dfx4ml_infra · presentation

Technical report v1.0 beta · PDF

  • DFX Manager: Verilog state machines drive ICAP and load partial bitstreams with no CPU.
  • DFX Streamer: BRAM and URAM buffers carry activations between network segments.
  • Two regions ping-pong, so one computes while the other is reconfigured. Tested on a Kria KV260.
  • Built at CERN under the supervision of Nicolò Ghielmetti.

HDL and Vivado + MCP Support: IntelliJ IDEA plugin

Verilog and SystemVerilog tooling for IntelliJ IDEA that hands a live Vivado session to an AI assistant over the Model Context Protocol. 1,500 downloads on the JetBrains Marketplace.

JetBrains Marketplace · github.com/Merge-Panic-Society/JetBrain-Verilog-Vivado-Plugins

1,500 downloads · rated 4.4

  • MCP server: thirty parameter-checked Vivado commands, from project creation to bitstream and programming. Safety-gated: loopback host only, a per-session bearer token, and raw Tcl behind an opt-in.
  • Language support: highlighting, completion, and cross-module linting for Verilog, SystemVerilog, Tcl, and XDC, through Icarus Verilog or Verilator.
  • Simulation and waveforms: run a testbench and read the VCD in an in-IDE waveform viewer, which the assistant can drive as well.
  • Vivado console: a bidirectional Tcl terminal over a socket, so the Vivado GUI stays usable while commands run.
  • Written in Kotlin on the IntelliJ Platform, for IntelliJ IDEA 2025.1 and later.
